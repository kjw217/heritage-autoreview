# 이미지 의미정확성 채점 기준 (품질 검수 사이트 · 체크리스트 v1.2)

묶음 파일의 항목마다 `orig_image`(원본)와 `overlay_image`(박스·마스크를 겹친 그림)를 **둘 다 Read 로 열어 본다**.
겹친 그림에서 박스는 테두리, 마스크는 반투명 색칠, 좌상단 `#번호 클래스` 가 `label.objects[].no` 와 같다.
라벨 텍스트(유산명·분류 경로·캡션·태그·객체 목록)를 그림과 대조해 아래 13개 세부 항목을 판정한다.

## 판정값
- `ok` 적합 · `minor` 보통(쓸 수는 있으나 다듬을 여지) · `major` 부적합(틀려서 고쳐야 함) · `na` 해당 없음
- `na` 는 `ocr` 에만, 현판·한자 글자 객체(`objects[].ocr`)가 없을 때만 쓴다. 다른 항목은 `na` 금지.
- 확실히 틀린 것만 `major`. 애매하면 `minor`. 근거 없이 `major` 를 주지 않는다. 반대로 눈에 보이는 오류를 `ok` 로 넘기지 않는다.

## 세부 항목 (키 · 무엇을 보나 · major 예)
| 키 | 이름 | 보는 것 | major 예 |
|---|---|---|---|
| src_quality | 원천 품질 | 사진 자체의 화질 | 흐림·노출 과다/부족으로 대상이 잘 안 보임 |
| src_target ★ | 학습 대상 | 국가유산을 찍은 사진인가 | 작업일지·공문 스캔, 사람·장비 위주 현장 사진 |
| heritage ★ | 유산 매핑 | 라벨 유산명·궁이 사진 속 대상과 같은가 | 낙선재 사진에 돈화문 매핑. 사진만으로 확인 불가하면 ok |
| class_path | 분류 경로 | 대>중>소>세 분류가 사진 성격에 맞는가 | 벽화 사진이 건조물, 수목 사진이 회화 |
| naming | 명칭 표기 | 캡션·태그의 유산 이름이 표준 명칭인가 | 격하 명칭, 틀린 전각 이름 |
| ocr | 현판 판독 | 현판 글자를 맞게 읽었나 (객체에 ocr 없으면 na) | 글자 오독, 순서 뒤바뀜 |
| obj_class | 객체 클래스 | 각 박스의 클래스 이름이 맞는가 | 문루를 전각으로, 벽화를 문양으로, 배경 아파트를 전각으로 |
| obj_bbox | 객체 위치 | 박스가 대상을 제대로 감싸는가 | 대상의 절반만 덮음, 화면 전체를 덮는데 대상은 일부, 옆 건물까지 포함 |
| obj_mask | 분할 마스크 | 색칠 영역이 대상 모양을 따라가나 | 하늘·바닥·담장까지 번짐, 대상의 큰 부분이 비어 있음 |
| obj_missing | 객체 누락 | 눈에 띄는 대상이 빠졌나 (작은 반복 문양 일부 누락은 minor) | 정면 현판·주요 전각에 박스 없음 |
| obj_false | 오검출 | 대상이 아닌 것에 박스가 있나 | 관람객·안내판·전선·나무에 박스 |
| caption | 캡션 | 캡션 문장이 사진 내용과 맞나 | 보이지 않는 사실(건립 연도 등)을 지어냄, 다른 유산으로 서술 |
| tags | 태그 | 태그가 사진에 실제 있는 클래스만인가 | 없는 클래스 태그, 있는 클래스 누락 |

클래스(10대): 전각, 문루·궁문, 담장, 석조물, 현판, 문양, 단청, 벽화, 수목·조경 등 라벨에 나온 값. 사진에 보이는 그 종류의 대상을 기준으로 본다.

## 출력
결과 파일에 항목마다 JSON 한 줄:
`{"data_id": "...", "checks": {"src_quality":"ok", "src_target":"ok", "heritage":"ok", "class_path":"ok", "naming":"ok", "ocr":"na", "obj_class":"ok", "obj_bbox":"ok", "obj_mask":"ok", "obj_missing":"ok", "obj_false":"ok", "caption":"ok", "tags":"ok"}, "comment": "minor·major 가 있으면 무엇이 문제인지 한 문장(한국어), 없으면 빈 문자열"}`
13개 키를 모두 넣는다. 다른 키는 넣지 않는다.
